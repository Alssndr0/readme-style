# 1. Write readme-style in Rust

Date: 2026-10-29. Status: accepted.

## Context

The first prototype was Python with markdown-it-py. It worked, but the tool's promise rests on
parsing a README exactly as GitHub does, it runs in pre-commit hooks and CI where start-up time and
installation matter, and it should be installable from the ecosystems READMEs come from (Python,
JavaScript, Rust, Go).

## Decision

Rewrite it in Rust, with comrak for Markdown and html5gum for HTML.

## Consequences

- comrak is a port of cmark-gfm, the parser GitHub uses, including tables, task lists, footnotes,
  autolinks and alerts, so block structure, anchors and the guard's rendering match GitHub.
- One static binary with no runtime: a few milliseconds per README, nothing to install but the file.
- The same binary is shipped through crates.io, PyPI (maturin, as ruff and uv do), npm (platform
  packages), GitHub releases and a GitHub Action. Python users lose nothing.
- The engine has no I/O of its own, so it can be compiled to WebAssembly for a browser playground.
- Contributors need Rust. The xtask crate keeps every development task in the same language.
